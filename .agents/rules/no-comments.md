## No Comments Rule

There should NOT be comments written for anything in this codebase.
The ONLY time there should be comments is when something is very confusing or complex and we need to explain why we did that certain thing.
Other than that, there should be NO comments at all:
- No file path headers (e.g. `// radius-frontend/...`)
- No obvious function/method docstrings or handler route docstrings
- No type/interface docstrings
- No JSX section markers (e.g. `{/* Header */}`)
- No step-by-step code narration (e.g. `// 1. Fetch user`, `// Check error`)
